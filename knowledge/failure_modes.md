# 无结果与异常排查指南

## 选址结果为空时的排查顺序
1. 城市过滤：检查上传文件的 city 列是否与所选城市一致；缺失时是否在上传时选择了城市。
2. 机坪净空高度：检查机坪表是否有 altitude_limit_m 列，且取值不小于 3 米；缺失会按 0 处理并被全部剔除。
3. 合格机坪数量：检查通过资格校验的机坪数量是否大于等于目标 P 值；P 大于合格机坪数时该 P 方案会被跳过。
4. 空域限制：检查候选机坪是否落在禁飞区或城市内环限制区内；这两类都会被直接剔除。
5. Stage2 门槛：检查衰减后覆盖单量是否达到 20；候选点彼此距离小于 280 米时会完全冲突，导致覆盖单量被大幅压减。
6. 落地条件：检查新建起降点的场地面积是否达到 80 平方米，经纬度是否合法。

## 常见误解与澄清
- 覆盖起降点数长期恒为 1：历史上是财务导向的贪心目标导致，现已改为物理网络覆盖优先，正常数据下不会出现。
- 平均配送距离为 0：样例数据里存在机坪与起降点同址的 0 距离边，加权后平均值会被拉低，不是算法错误。
- 内环限制区内的机坪被保留：与当前实现不符，当前是直接剔除。
- 市场渗透率调大后覆盖点变多：不会发生；渗透率只影响财务演算，不改变覆盖结果。
- 上传数据后不传 dataset_id：会退回使用内置样例数据，结果与上传数据无关。
- 服务重启后继续用旧 dataset_id：注册表已清空，会提示未知 dataset_id，需要重新上传。

## 结果可信度检查
- 对比漏斗数字是否单调：候选数应大于等于 Stage1 通过数，Stage1 通过数应大于等于 Stage2 选中数。
- 检查推荐方案的覆盖点数是否为所有 P 方案中最多；推荐规则是覆盖点数优先、平均距离次之。
- 检查结论中的数字是否都能在工具返回里找到，没有出处的数字不应采信。
